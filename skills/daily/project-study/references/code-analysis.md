# Code Analysis — 源码研究证据

用于回答具体函数/模块/调用链/设计问题，以及学习过程中必须验证的实现连接。**这里是 Agent 的研究步骤，不是初学者作业。** 如果正处于教学会话，研究完仍按[学习流程 `3](learning-workflow.md)拆成一个个源码片段带读。

## 研究步骤

1. **定入口**：确定本次要解释的行为、输入输出，定位实际 route、CLI、事件、任务或 API。完成：真实文件和入口符号可查。
2. **走主链**：沿调用者到被调用者追到一个可观察结果，核对关键参数、返回值、外部副作用；对动态注册/注入找实际绑定点。完成：主要跳转都有路径/符号，缺失连接标待查。
3. **看状态**：找出至少一次关键对象的创建、转换、存储或释放，注明异步/事务/缓存边界。完成：数据/控制变化有语句依据。
4. **查边界**：核对一处分支、异常、失败路径或测试。完成：能说明一个限制，或明确尚未覆盖。
5. **谈取舍**：先陈述实现事实，再提出收益/代价和可能替代方案；推测作者动机必须标推断。完成：事实与设计假设可区分。
6. **设计核验**：找测试或静态推演问题；真实运行须获授权。完成：给出一个可复现的核验动作。

## 证据层级

| 类型 | 记录要求 |
| --- | --- |
| 源码确认 | 相对文件路径、真实符号，实际核验才附行号 |
| 文档陈述 | 标为文档说法，未核对实现不当源码事实 |
| 静态推演 | 写出依赖语句、分支及未覆盖的动态条件 |
| 运行观察 | 仅记录实际命令、环境和结果 |
| 设计假设 | 用“可能”“可选方案”，与实现事实分开 |

**完成与输出**：独立技术问答按“结论 → 代码证据 → 数据/边界 → 验证方式”裁剪；教学会话只呈现当前可消化的真实片段及下一跳，并回到原单元锚点。没有执行的测试不得写“通过”。
