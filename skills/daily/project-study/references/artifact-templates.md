# Artifact Templates — 学习状态的数据形状

**仅在需要实际保存或更新学习资料时读取。** 行为流程和单元状态的判定来自 [学习流程](learning-workflow.md)，本文件只定义文件结构、必要字段和写入顺序。

## 根目录约定

学习数据放在用户明确允许的目录；项目根目录的 .project-learning/ 只是候选位置。Skill 包内只存教学规则。

    .project-learning/
      overview.md
      roadmap.md
      progress.md
      sessions/
        YYYY-MM-DD.md
      notes/
        topic.md

notes/ 只在值得单独沉淀时创建。一个日期多次学习时，往同一 session 文件追加带时间和单元 ID 的区块。

    - 学习目标：
    - 源码基线（branch、commit、dirty 或非 Git）：
    - 核验日期：

    ## 职责、输入输出与运行边界
    ## 代码地图：模块职责与依赖、已验证的主调用链
    ## 知识地图：先修概念、关键机制、学习依赖
    ## 最小可观察功能切片与源码证据
    ## 暂未覆盖或仍待核实的连接

    # 学习路线
    - 总体能力目标：
    - 规划依据：
    - 调整记录：日期、原因：

    ## U01 · 单元名称
    - 状态：
    - 能力目标：

    - 真实文件与符号：
    - 2–4 个核心问题：
    - 学习动作：
    - 预期完成证据：
    - 实际验证证据：

状态值与流转由学习流程统一定义；保留原单元 ID 和完成记录，路线变更时写明原因。

## progress.md：唯一续学指针

    # 当前学习位置
    - 项目：
    - 最近核对的源码基线：
    - 更新时间：
    - 当前单元：Uxx · 名称
    - 当前状态：

    ## 已有证据的掌握内容
    ## 当前疑问或误区
    ## 关联路线与最近会话
    ## 下一次第一步：一条具体动作

本文件应简短；详细历史保存在 roadmap 与 sessions 中。更新会话和路线后，最后写 progress.md。

## sessions/YYYY-MM-DD.md：按次增量记录

    # YYYY-MM-DD
    ## HH:MM · Uxx · 单元名称
    - 本次目标和查看的文件/符号：
    - 学习者自己的解释：
    - 静态推导及代码证据：
    - 实际运行结果（若确实执行）：
    - 发现的误区、补充问题：
    - 状态判定及依据：
    - 下一步：

未取得学习者自己的解释时写“待学习者回述”；不要以助手生成的摘要冒充学习者掌握。

## notes/topic.md：少量高价值知识

    # 主题
    - 项目 / 单元 / 源码基线：

    ## 核心问题与一句话结论
    ## 代码路径、真实机制和设计取舍
    ## 已有验证与未验证的假设
    ## 容易混淆的边界
    ## 下次复习的问题

只对明确的核心机制、关键调用链、经验证的排障或复杂疑问单独建笔记。

## 写入一致性

1. 核实目标目录与用户授权，读取已有文件；按增量方式追加或更新相关区块。
2. 先保存 session 与证据，再更新 roadmap 状态，最后更新 progress 指针。
3. 保存后检查所写文件可读、当前单元及下一步一致。源码版本变化时保留旧基线证据和对应说明。
4. 将敏感信息从学习记录中排除；项目内学习文件是否纳入 Git 由用户自行选择。
