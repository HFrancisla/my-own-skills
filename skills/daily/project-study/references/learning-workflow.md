# Learning Workflow — 学习路线、导师带读与验收

这是项目学习的执行顺序；只执行当前意图所需阶段。**源码侦察是 Agent 的准备，源码带读才是学习者的课程**。对新手优先使用导师带读；对明确要求挑战或已有表现证据的学习者，允许跳过已掌握的部分。

## 1. 绑定项目并建立最小双地图

1. **绑定**：优先使用指定项目路径/仓库；核对源码可读范围、Git 分支/commit/工作树（或非 Git）和学习目标。未定时间按 45 分钟规划，可调整为 30–90 分钟。远端 clone 先获得授权及落点。
2. **侦察**：先看 README、依赖和入口，再检查模块边界与代表性测试；沿与目标有关的一个功能切片追踪“入口 → 核心处理 → 可观察结果”，遇到动态注入/注册等未确认连接做标记。复杂追踪按[源码分析](code-analysis.md)核实。
3. **双地图**：代码地图写模块职责、依赖方向、一个有文件/符号依据的主链及未覆盖区域；知识地图写读懂该链所需的概念、前置关系及“已观察掌握 / 待确认 / 待补”。已掌握必须有学习者回答或实践证据；未知基础标“待确认”，无需先考试。

**完成**：项目和基线可定位；至少一个真实入口与一个可核验的结果方向已经找到。地图可以很小，后续逐步扩展；内部追过的完整链不等于已经教过。

## 2. 规划学习单元

以“学习者能独立证明的能力”划分 U01、U02……，从最小可观察链路出发，再研究抽象、状态、异常边界与取舍。每单元记录：能力目标、真实文件/符号与首个带读入口、必要先修知识及依赖、2–4 个源码问题、带读/练习/验证动作、预计时长与状态。

**依赖排序**：先选与目标匹配的功能切片，再按学习者确有的知识证据排单元。缺一个局部概念时优先在当前单元补讲；关键依赖确实阻塞时调整未来单元顺序，并记录原因。保留既有 ID 和历史完成记录。

**完成**：每个单元可指出首个应展示的真实代码位置；U01 可立即开始带读。未核实的候选标“待核实”，不当作确定的源码依据。

## 3. 带学当前单元：导师带读

**教学模式取决于学习者，不取决于 Agent 侦察深度。** 先判断学习者是否实际看过相关代码：
- 新项目、基础未知、明确说“不了解/不会/带着我读”：从`基础讲解`进入。
- 已见过一些代码：接续`源码示范`，缺概念时短补讲。
- 学习者已展示理解或主动要求挑战：进入`引导练习`或`独立验证`，仍核对真实源码。

### 每次示范只推进一个跳转

1. **说明目标**：用一两句话讲本段解决的具体行为、输入输出和必要的 2–3 个术语。
2. **展示源码**：实际读取并展示一小段关键代码（通常 5–20 行，按复杂度调整），标出项目相对路径、函数与上下文；解释变量来源和关键语句。
3. **示范下一跳**：实际打开被调用的符号，解释参数如何传入、为什么看这里；尚未核实的跳转标明待查。
4. **跟读确认**：结束在“这里是否清楚，要继续下一跳还是补讲？”或一个对**刚讲过的**局部行为的简单确认。用户选择继续时沿锚点再示范一跳；困惑时缩小片段并补讲。

**完成**：学习者真正看到首段实现与至少一个经核实的符号跳转；本轮留下准确的阅读位置及一个下一步。Agent 自己的调用链摘要、文件名列表不算教学完成。

### 阶段切换门槛

| 当前 → 下一阶段 | 可观察的进入条件 | 下一轮动作 |
| --- | --- | --- |
| `基础讲解` → `源码示范` | 目标行为、输入输出和首段必需概念已讲清，真实入口已定位 | 展示入口代码并亲自解释 |
| `源码示范` → `引导练习` | 已展示并解释一个真实跳转；学习者表示愿意练习或已对局部内容表现出理解 | 只问已带读代码的一小步定位/解释，给文件或符号线索 |
| `引导练习` → `独立验证` | 学习者已尝试一个局部问题并收到反馈，具备撤除提示的条件 | 让其独立解释**已学习的**主链并给源码证据 |
| `独立验证` → 单元完成 | 学习者自己的解释与可定位的依据满足本单元目标 | 记录证据、状态与下一动作 |

学员主动要求直接挑战时可跳级；挑战遇阻即回到合适的示范步骤。**“我不会”意味着需要带读，不是`needs_review`证据**；只有完成带读、引导尝试后仍显现具体误解，才考虑该状态。

**反例**：新手 U01 尚未看过 `interactive-mode.ts` 中 `this.session.prompt(userInput)` 的上下文，下一步应先展示那段代码并解释 `userInput` 与 `session`，再带读下一跳；不应先布置“独立追到模型流并定位 user 消息构造”的整链任务。此例是教学粒度示范，真实符号必须在目标仓库核验。

**本轮完成**：回复指出当前单元、实际已带读位置、教学阶段、源码依据以及**一个**可执行的下一动作。仍在讲解/示范时单元状态保持 `in_progress`。

## 4. 验收与练习

单元结束用 2–4 个与**已学范围**对应的问题，让学习者独立解释职责、主流程、依据及一个边界/取舍；Agent 的总结不是其掌握证据。

| 单元状态 | 依据 |
| --- | --- |
| `pending` | 尚未开始 |
| `in_progress` | 正在讲解、示范、引导或验证；同项目最多一个 |
| `blocked` | 需要的权限/环境/材料缺失，写明恢复动作 |
| `needs_review` | 带读和练习后独立尝试仍有具体理解缺口，记误区与补练 |
| `completed` | 学习者独立解释关键机制并给出处；运行型单元另需真实运行记录 |

解除阻塞或补练后回到 `in_progress`；补练达到标准可从 `needs_review` 完成。适合时安排独立定位测试、静态推演或最小实验；运行/改动仍须授权。普通代码理解单元不以修改业务代码为必需条件。

**完成**：状态、学员证据或缺口和下一步明确；讲完不自动等于学会。

## 5. 恢复与保存

1. 有已授权学习目录时，读取 `progress.md`、对应的 `roadmap.md` 单元和最近 `sessions/`；恢复单元、教学阶段、**实际向学习者带读的**位置、独立掌握证据和下一动作。没有目录时只使用可靠的对话上下文。
2. 核对相关代码基线；变化部分重查，保留旧证据所属版本。
3. 输出续学锚点，继续当前合适阶段；旧记录缺阶段或带读证据时从基础讲解/源码示范恢复，不从 Agent 已调查范围推断学员掌握。
4. 获得写入授权时按[学习产物模板](artifact-templates.md)保存；未授权时给可复制的锚点。

**完成**：下一次可从一个真实代码位置和明确动作接上，且没有虚构历史或越权写入。

## 6. 间隔复习与跨单元回顾

单元 `completed` 后可建议第 **1、3、7 天**做短时回忆，按学员反馈调整；复习是独立维度，不改写最初完成证据，也不增加第二个 `in_progress`。只有用户再次学习或要求复习时才检查到期项；本 Skill 不会自动定时提醒。

复习时先让学员回忆 1–2 个旧问题或定位已学过的代码，再对照源码；如果忘记，改为一小段导师示范。记录复习日期、回答证据、结果（仍掌握/需巩固）、下次建议日期。新单元依赖旧知识时可插入一次简短回顾，由用户决定是否先复习。

**完成**：实际复习有学员反馈及下一次建议；仅规划复习时写“待复习”，不伪造完成记录。保存字段见[学习产物模板](artifact-templates.md)。

## 7. 整个项目验收

让学习者独立解释项目职责与模块、至少一条端到端调用链和一个关键设计取舍，并提供源码或授权实验依据。列出仍未覆盖的区域与进阶路径；项目完成依能力证据，而非文件阅读数量。
