# 项目学习流程

## 1. 识别路线

确定项目、学习范围和源码基线（分支、commit、工作树状态或非 Git），检查已存 `roadmap.md`、`progress.md` 和最近 `sessions/`：

- **路线完整，指针有效**：恢复当前 Uxx、教学阶段和真实带读位置。
- **路线完整，指针失效**：根据路线与会话记录修复；证据不足标待确认，从可核实位置继续。
- **路线缺失或遗漏核心模块**：进入首次规划，保留现有 Uxx 和完成证据。

## 2. 首次规划

1. **横向扫描**：读 README、构建配置、入口、主要模块、数据/状态、外部边界和测试；列模块职责、依赖和代表路径。
2. **纵向核实**：找一条「入口 → 核心处理 → 结果」链，确认 U01 可带读的文件与符号；复杂连接参照[源码分析](code-analysis.md)。
3. **全局路线**：按先修依赖一次性安排 U01…Uxx，覆盖所有核心模块。每个单元给出能力目标、依赖、代表源码、关键问题、教学/练习方式和可观察验收标准；注明可选范围、排除理由与待核实项。大型项目可按子系统先拆完整主线，再细化单元。
4. **保存并展示**：依[产物结构](artifact-templates.md)写 `overview.md` → `roadmap.md` → `progress.md`，回读核对覆盖、U01 与指针。向学员展示所有单元的顺序与阶段目标，然后带读 U01。

完成：每个核心模块都对应 Uxx，U01 入口可定位，保存状态明确。

## 3. 带读当前单元

从指针继续；基础未知先讲概念，已有知识或学员主动挑战可跳级。每轮按「目标/输入输出 → 展示并解释约 5–20 行真实代码 → 核实一个调用/数据跳转 → 让学员选择继续、补讲或练习」进行。

教学阶段：`基础讲解` → `源码示范` → `引导练习` → `独立验证`。从示范转练习需已教过真实跳转；进入独立验证前需有学员的局部尝试与反馈。遇到理解缺口就补讲当前单元。

完成：记录实际展示的文件/符号、学员反馈和一个下一动作；Agent 自己读过的代码不计教学。

## 4. 验收、状态与调整

仅就已教内容提 2–4 个问题，让学员独立解释职责、主链、源码依据及边界/取舍；运行型目标需真实运行记录。状态：

- `pending`：未开始；`in_progress`：正在教或验证（最多一个）。
- `completed`：独立掌握证据满足验收标准。

未掌握且能继续时维持 `in_progress`；完成后进入原路线的下一个 `pending`。仅当模块重大遗漏、源码重大变化或目标变更时修订路线：保留稳定 ID、已完成证据及原基线，追加新 ID，记录版本和变更原因。

## 5. 记录与恢复

每轮先记录 `sessions/YYYY-MM-DD.md` 中真实教学与反馈，再更新 `roadmap.md` 单元状态/证据，最后更新 `progress.md` 的唯一指针；写后验证版本、Uxx 与带读位置一致。

项目最终验收由学员独立解释整体架构、端到端主链和关键取舍，并指出未覆盖的可选范围。

**每轮回复**：当前 Uxx、实际带读位置、学员证据、一个下一动作。
