# Learning Workflow — 项目学习的阶段与验收

用于首次规划、单元教学、续学和复盘。依次完成项目绑定、双地图、路线、带学、验收与恢复；只进入本次请求所需的阶段。

## 1. 绑定项目与目标

1. 优先使用用户指定的路径或仓库；其次是能够唯一确定的当前工作区。多个候选时询问具体项目。
2. 记录本轮能力目标（如“解释请求处理主链”）。未约定时间时按 45 分钟设计单元，必要时调整到 30–90 分钟。
3. 检查可访问的项目根目录与源码版本。远端 clone 先取得本地落盘位置及网络操作授权；仅能读取部分资料时标注范围。

**完成门槛**：项目来源明确，学习目标可验证，源码可读范围及基线（分支、commit、工作树变化，或非 Git）已说明。否则先补全当前缺口。

## 2. 渐进侦察与双地图

按顺序完成三轮最小检查：

1. **外部视角**：阅读项目说明、依赖/构建配置和可见入口，提出项目职责、输入输出与技术栈的初步假设。
2. **模块视角**：在源码中核验入口、模块边界、主要依赖方向与代表性测试，选一个与学习目标相关的端到端功能切片。
3. **实现视角**：沿该切片的入口、核心逻辑与结果点追踪至少一条调用路径；遇到依赖注入或动态注册时标注尚未确认的连接。需要细节时加载 [源码分析](code-analysis.md)。

产出两张地图：
- **代码地图**：模块职责及依赖、入口、一条有证据的代表性调用链、尚未覆盖区域。
- **知识地图**：读懂该调用链所需的前置概念、核心机制、学习依赖与本轮可跳过的知识。

知识地图要标记本轮必要的前置知识及其学习依赖，区分“已观察到掌握 / 待确认 / 待补”。后续单元以它决定讲解起点与先后顺序。

**完成门槛**：至少有一个代码入口和一条可核验的主路径；关键地图连接附文件/符号依据；未验证部分被显式标注。只有目录结构还不算建图完成。

## 3. 规划学习单元

依赖实际项目地图和学习目标，为单元分配稳定 ID（U01、U02……），按“可独立证明的能力”而不是文件数划分。建议从最小链路进入，再按需研究核心抽象、数据状态、异常边界、设计取舍和综合复盘。

每单元必须有：
- **能力目标**：学习者最终能够解释、追踪或判断的具体行为。
- **阅读范围**：真实文件/符号及可能的相关测试。
- **先修概念及教学入口**：当前已知的知识缺口、可直接打开的首个文件/符号，以及应由助手示范的最小代码跳转。
- **2–4 个核心问题**：问题必须能由代码或可控实验回答。
- **学习动作与证据**：示范、带提示练习、独立解释及可授权的最小验证；有基础时可加入预测。
- **预计用时与状态**：通常 30–90 分钟；最多一个单元处于 in_progress。

按知识依赖安排路线。进入单元后发现知识缺口时，在原单元内插入补讲或小练习，保留单元 ID 和进度锚点。

**完成门槛**：每个单元都有上述字段；U01 可以立即从已核实的文件/符号开始学习；尚未定位的内容标为待核实。需要落盘时加载 [学习产物模板](artifact-templates.md)。

## 4. 带学当前单元

每轮先指出当前单元、教学阶段、已核实的代码位置和一个可执行动作。**教学阶段**独立于单元状态，依次可为：`基础讲解`、`源码示范`、`引导练习`、`独立验证`。按已有回答和用户表述选择起点；没有可靠掌握证据时，从首次学习的入口开始，不把诊断变成准入考试。

| 前置知识情况 | 起点 | 立即提供 |
| --- | --- | --- |
| 未知、首次接触或缺少先修知识 | 基础讲解 | 本单元要解释的行为、2–3 个必要概念、最小源码入口 |
| 了解部分概念 | 源码示范 / 引导练习 | 缺失概念的短补讲、文件/符号线索、一个小步骤 |
| 有证据表明已熟悉，或用户要求挑战 | 引导练习 / 独立验证 | 局部预测或独立追踪，并用源码核对 |

按选定起点逐步推进，每步达标才向下一步撤除提示：

1. **基础讲解**：交代目的、输入输出和必需概念。完成：已明确一个具体行为、其输入输出和跟读首段代码所需的 2–3 个术语；此步不以独立答题验收。
2. **源码示范**：助手实际读取代码，展示“为什么从这里进入 → 关键语句做什么 → 下一跳去哪里”，标注路径与符号。完成：至少一个入口到下一符号的跳转已由源码核对，且明确给出可重复的定位路径。
3. **引导练习**：给出一个短的定位或解释动作，先提示文件/位置，再逐渐只留符号线索；根据回应补讲和纠偏。完成：学习者至少对一个局部行为尝试解释或追踪，并获得具体反馈。
4. **独立验证**：让学习者脱离提示解释单元主链或关键机制，并指出源码证据；适用时安排静态推演或**获授权**的运行验证。完成：有学习者自己的解释及可核对的依据；不足时回到引导练习。

**预测的使用条件**：学习者已接触相应片段，或明确想直接挑战时，预测一个局部行为并立即对照源码。首次学习时由示范带路；已掌握基础后再撤除提示。

**卡住时的恢复动作**：听到“不会”“从哪里开始”或看到难以回答的首次预测题，就回到`基础讲解`或`源码示范`，指出一个真实入口并现场示范一跳；再给一个可跟随的小动作。简单技术问题先直接解答，之后返回原单元锚点。

**完成门槛**：本轮所讲的关键行为有源码依据，明确当前教学阶段与**下一次一个动作**。只完成讲解/示范时维持 `in_progress`；单元是否 `completed` 由第 5 节的独立证据判断。

## 5. 复盘与单元状态

单元结束时选择 2–4 个可对照源码的问题，让学习者独立回答“解决什么问题、流程怎么走、证据在哪里、关键失败路径或取舍是什么”。以其回答和证据判定，不用 AI 代写的总结充当掌握证明。

| 当前状态 | 触发条件 | 下一状态 |
| --- | --- | --- |
| pending | 开始该单元 | in_progress |
| in_progress | 遇到环境/权限等障碍 | blocked |
| in_progress | 经过示范和引导练习后，独立解释仍暴露具体理解缺口 | needs_review |
| blocked / needs_review | 解除障碍、补充验证 | in_progress |
| in_progress / needs_review | 独立解释并给出可定位的依据 | completed |

- **代码理解单元**：学习者能够独立解释核心机制，并对应到源码、静态推演或已核验的测试。
- **实际运行单元**：除独立解释外，需有真实运行记录；只读推导不能代替实测。
- **需要补练**：写清具体误解和下一道验证问题；阻塞时写清阻碍与可选替代动作。
- **刚进入单元时不会回答**：按第 4 节回到示范或引导练习，保持 `in_progress`；在真正独立尝试后才判定 `needs_review`。

**完成门槛**：明确给出状态、依据和下一步；达到完成标准才推荐下一单元，保持同一项目最多一个 in_progress。

## 6. 恢复学习和保存锚点

当用户要求继续时：
1. 如有已授权的进度目录，先读 progress.md、对应 roadmap 单元及最近一次 session，恢复**当前单元、教学阶段、已掌握证据与下一个动作**；旧记录缺少教学阶段时根据已有证据判断，仍不清楚则从源码示范起步。没有目录则使用聊天中可靠的上下文。
2. 比对相关源码基线及工作树变化；相关代码变化时重查受影响结论，保留历史证据所对应的版本。
3. 给出**续学锚点**：当前单元、已经验证的理解、未解决问题、下一次具体第一步。
4. 用户允许写入时按 [学习产物模板](artifact-templates.md) 更新学习活动与路线，最后更新 progress.md；没有授权则提供聊天内可复制的锚点。

恢复时根据先前的知识缺口与提示级别安排下一步。学习者的解释和助手提供的示范分别记录，前者才可作为掌握证据。

**完成门槛**：续学回答指向**一个**可执行动作且没有伪造上次进度；如实际写入，核对目标文件存在且记录可供下次定位。

## 7. 整个项目的学习验收

让学习者独立说清项目职责与主要模块，解释至少一条端到端调用链、一个关键设计取舍，并提供可核验的源码推导或真实实验。输出尚未覆盖的区域和进阶方向。项目完成由可解释性和证据决定，而非全部文件都看过。
