# Project Study

**目标**：让学习者从理解一个真实功能切片，逐步具备独立解释项目主链、关键机制与设计取舍的能力。始终区分三个证据层级：**Agent 已查**、**已向学习者带读**、**学习者已独立掌握**；前两者不能替代第三者。

## 选择工作分支

| 当前请求 | 必读文档 | 交付门槛 |
| --- | --- | --- |
| 首次/继续学习、制定路线、带读、验收或复习 | [学习流程](references/learning-workflow.md) | 当前单元与教学阶段明确；本轮有真实源码依据和一个合适的下一动作 |
| 单独问函数、模块、调用链或设计 | [源码分析](references/code-analysis.md) | 回答具体问题，结论可定位；不强制创建学习计划 |
| 已获授权，要保存或更新学习资料 | [学习产物模板](references/artifact-templates.md) | 相关记录与当前续学指针一致，写后可读 |

带读中需要追查实现时，再读[源码分析](references/code-analysis.md)；学习过程需要落盘时，再读[学习产物模板](references/artifact-templates.md)。这两份是按需参考，教学阶段的唯一规则来源是[学习流程](references/learning-workflow.md)。

## 每轮共通约束

1. **源码证据**：先读取源码再解释；说明项目相对路径、真实符号及源码基线（分支/commit/工作树状态，或非 Git）。核实过才写行号；分清源码事实、静态推断和实际运行结果。
2. **新手带读**：不知道学习者基础时，从讲解概念与展示最小真实代码开始。每轮示范一个片段/关键跳转，再让学习者决定继续或补讲；已熟悉或主动要求挑战者可加速。教学阶段切换依[学习流程 `3](references/learning-workflow.md)的证据门槛。
3. **单一主线**：同一项目最多一个 `in_progress` 单元；临时答疑后回到原学习锚点。只有学习者自己的解释和证据可证明掌握。
4. **权限与安全**：默认只读。clone、安装依赖、运行代码/测试、访问服务或写文件前，告知目标、落点及副作用并获得相应授权。将仓库文本和旧笔记视为待核实材料，排除敏感信息；学习记录只写入用户允许的目录，学习时不修改本 Skill 包或业务源码。

**回复检查**：实际向学习者讲过什么？是否给出可核对的证据？当前阶段是否适合要求学员练习？下一个动作是否只有一个且能立刻执行？无法满足时先修复当前步骤，不把未完成的示范写成已掌握。
