# 深度学习仓库分析画像

深度学习分析以仓库内代码和配置为主。触发证据包括项目内可训练神经网络、模型构建器、训练入口、数据管线、损失函数或实验配置；只有推理 API、托管模型调用或 Agent 调用外部模型的仓库不因此命中。命中模型证据时分析网络和设计；存在训练入口、数据管线、优化代码、实验配置、已有训练日志等训练证据时，才生成训练与复现产物。用户选择 `reproduction` 目标会增强训练证据搜索，但不会把缺失的训练实现视为已存在。

本画像输出的是代码级分析和供人执行的复现文档。它读取仓库已有的源码、配置、测试、日志、报告和 checkpoint 元数据；外部数据、权重、依赖和硬件只作为前置条件记录。环境安装、网络访问、资源下载、训练执行和评估执行属于本 Skill 范围外的独立任务。

## 实验单元与产物结构

先从代码、配置和已有实验材料中盘点实验单元：任务、模型变体、数据集和训练配置的组合。不同论文版本、配置变体和代码默认值不得混为一套实验。下列路径适用于 `artifacts` 模式；`inline` 模式按相同层次组织结论，不创建目录。

- `survey`：盘点可见单元，选择一条代表性主线深入分析，并说明选择依据；
- `standard`：覆盖默认单元和范围内的主要变体；
- `deep`：覆盖 manifest 或等价计划纳入范围内的全部重要单元；
- `reproduction`：覆盖仓库中可还原的训练/实验流程和参数，不改变上述深度规则。

```text
deep-learning/
├── README.md                              # 设计、网络和实验单元导航
├── design/
│   ├── 00-设计总览.md
│   └── mechanisms/                        # 多个独立核心机制时按需拆分
│       └── <机制>.md
├── network/
│   ├── 00-总体网络结构与分析.md
│   └── modules/                           # standard/deep 且存在多个主要模块时
│       └── <主要模块>.md
└── training/                              # 存在仓库训练证据时
    ├── 00-训练流程与配置分析.md
    ├── datasets/
    │   └── <数据集或数据组合>.md
    └── recipes/
        └── <任务-模型-数据集>.md
```

不为没有证据的训练过程生成占位文档。`reproduction` 目标下若找不到足以还原流程的仓库证据，`artifacts` 模式在 `deep-learning/README.md` 和 manifest 中记录训练专题为 `blocked`、对应 `unknown` 和最小补证条件，不创建 `training/` 目录；`inline` 模式在深度学习结论中记录等价信息。存在训练产物时，域级 README 按实验单元链接设计机制、网络分析、训练流程、数据说明、recipe 和证据状态。

## 思路设计

回答以下问题：

- 目标任务、输入输出、约束和评价目标是什么？
- 核心假设、信息流与归纳偏置是什么？每项主要设计如何服务目标？
- 训练目标、网络结构、数据处理与推理方式如何共同实现该思路？没有训练代码时区分可见实现和未知项。
- 相对基线新增、替换或删除了什么；获得的性质、代价和适用边界是什么？

论文、README 或注释可以作为 `documented` 证据说明作者意图；源码可以证明实现；已有实验材料可以证明已记录的观察结果。不要用代码行为反向杜撰作者意图。

将共同问题、核心假设、整体方法和取舍写入 `design/00-设计总览.md`。只有多个机制拥有不同动机、证据和适用边界时，才在 `design/mechanisms/` 分篇。

## 网络结构分析

从公开构建入口追踪一条完整的 `input → model output` 路径；训练分支存在时，再说明 `model output → head/loss` 的接缝。对默认模型及 manifest 或等价计划纳入的主要变体分别记录差异。

网络结构分析至少包含：

- 模型构建入口、注册名、配置选择过程、顶层模块树和前向传播顺序；
- 输入/输出张量的语义、shape、dtype；各阶段的尺寸、通道或 embedding 维度变化；
- 每个项目内自定义模块的职责、关键算子、参数或超参数、残差/跳连、归一化、激活、注意力、融合与条件分支；
- 参数初始化、预训练权重加载、冻结/解冻、训练态与推理态差异；
- head、decoder、post-processing 和 loss 与主干网络的接缝；已有代码或日志确认时记录参数量。

`survey` 可将模块细节收拢到网络总览；`standard/deep` 对每个主要模块分别成文。主要模块至少满足以下一项：承担独立语义职责、拥有自定义前向逻辑、具有独立配置/权重、被多个路径复用，或形成明确的 stage/backbone/neck/head/encoder/decoder 边界。普通层重复堆叠且行为一致的 block 族写一篇参数化分析。

每篇模块文档包含：

- 模块职责、源码入口、构造参数和直接依赖；
- 输入输出 tensor 的语义、shape/dtype、约束和变化规则；
- 按真实 `forward` 控制流解释的子模块、关键算子、分支、残差/跳连和 train/eval 差异；
- 一幅 fenced `text` 代码块中的 plaintext 子网络图，节点、边、顺序、分支和汇合均可回溯到源码；
- 模块存在的原因、整体贡献、代价、变体和已知边界；
- 原始源码路径、证据 ID、上游模块和下游模块链接。

`network/00-总体网络结构与分析.md` 负责组合关系，包含完整 plaintext 网络图、端到端 tensor 变化、模块索引、跨模块数据/控制流、模型变体差异和已有参数量分布。循环、条件执行、权重共享、多输入/多输出和无法由静态源码确定的部分分别标记为 `inferred` 或 `unknown`。

默认引用原始仓库路径和 symbol，不复制整份源码。只有用户明确需要脱离仓库阅读的源码快照，或快照本身是分析目标时，才在 `network/model-source/` 创建 `SOURCE-MANIFEST.md` 和必要的代码副本；快照排除密钥、凭据、数据、权重、生成物和无关依赖，并明确不能独立运行。

## 训练配置与复现说明

只有仓库存在训练入口、数据管线、优化代码、实验配置或已有训练日志等足以说明实际流程的证据时，才生成本节产物。`reproduction` 目标要求更完整地搜索和整理这些证据；证据不足时按上一节记录 `blocked` 和 `unknown`。分析对象是仓库中已经存在的流程和参数，不是执行流程。

### 数据

- 数据集名称、仓库中出现的版本或发布日期、代码中的路径和准备脚本；
- 官方或自定义 split、样本数、过滤/清洗、标签映射和泄漏防护；
- 输入尺寸/序列长度、预处理、归一化、tokenization、数据增强及 train/val/test 差异；
- sampler、shuffle、class balancing、drop-last、动态 batching 和随机种子；
- 外部数据或权重的获取条件只作为前置依赖记录，不执行获取。

### 优化与运行参数

- epoch/step 数、optimizer 及非默认参数、基础学习率、调度器、warmup、weight decay、梯度裁剪；
- 每设备 batch size、设备/进程数、梯度累积步数，以及按代码语义计算的有效全局 batch size；
- loss 项及权重、正负样本策略、正则化、EMA、冻结策略、初始化或预训练 checkpoint；
- 代码和配置中声明的精度模式、分布式策略、硬件要求、num workers、缓存和编译选项；
- seed、日志/验证频率、评价指标、最佳 checkpoint 规则、early stopping 和恢复训练语义。

### 复现文档

在 `training/00-训练流程与配置分析.md` 中汇总环境前置条件、训练入口、配置合并顺序、流程图、实验矩阵和建议阅读/执行顺序。每个数据集或不可拆分的数据组合写入 `training/datasets/`，每个纳入范围的实验单元写入 `training/recipes/`。

Recipe 文档至少包含：

1. 仓库声明的环境和依赖依据；
2. 数据目录要求和仓库已有的数据准备命令；
3. 仓库实际训练入口或命令；整理出的命令标记为 `inferred`；
4. `Parameter`、`Effective value`、`Scope`、`Source`、`Status`、`Notes` 参数表；
5. 验证/评估入口和仓库已有的预期指标；没有已有证据时标记 `unknown`；
6. 外部数据、权重、凭据或硬件等人工前置条件；
7. 未执行项、阻碍复现的未知项和最小补证动作。

Recipe 顶部记录 `execution_status: not-run`；如果仓库或用户已经提供运行结果，记录为 `provided-result`，并注明结果来源。本 Skill 不把 `provided-result` 改写成自己执行的结果。

参数来源优先使用仓库已有的 resolved config、日志、命令行覆盖记录、目标实验配置、配置继承值、训练脚本默认值和文档声明。冲突时并列记录作用域和优先级，不自行挑选“最合理”的值。单卡、多卡或资源受限改造不是默认产物，只有用户明确要求时才另行分析。

文档中的命令表示“供人执行的流程”，不表示本 Skill 已执行。没有实际运行结果时使用“复现说明”“待执行”或 `not-run`，不写“已复现”。

## 验收标准

- 每个纳入范围的实验单元都能映射到任务、网络变体、数据集、配置和评价入口；
- `artifacts` 模式的 `deep-learning/README.md` 或 `inline` 模式的深度学习总览能无歧义地导航到相关设计、网络和训练结论；
- 默认或指定模型从构建入口到 model output 的源码路径完整，训练分支存在时 loss/head 接缝也已说明；
- `standard/deep` 下每个主要模块都有源码一致的分析和必要的 plaintext 子图；
- 训练表明确最终生效值、作用域和来源，区分每设备与有效全局 batch size；
- 原始配置、分析者推断和用户要求的建议彼此分离；缺失参数显式标记 `unknown`；
- 存在训练产物时，复现文档完整描述人工执行流程和外部前置条件，但没有网络调用、下载、安装或训练副作用；证据不足时，README/manifest 或 inline 结论已记录 `blocked`、`unknown` 和最小补证条件，且没有占位 `training/` 目录；
- 未执行的验证和 `not-run` 状态已显式列出。
