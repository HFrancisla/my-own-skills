# 深度学习仓库分析画像

深度学习是能力画像，可与 CLI、Library/SDK、Backend 等同时命中。触发证据包括项目内可训练神经网络、模型构建器、训练入口、数据管线、损失函数或实验配置；只有推理 API、托管模型调用或 Agent 的仓库不因此命中。

先确定实验单元：任务、模型变体、数据集和训练 recipe 的组合。仓库包含多种模型或任务时，完整盘点全部单元；`survey` 选择代表性主线并说明选择依据，`standard` 覆盖默认及主要公开变体，`deep` 或 `reproduction` 覆盖用户指定与官方复现实验。不同论文版本、配置变体和代码默认值不得混为一套实验。

## 产物结构

检测到深度学习画像时，以如下目录组织产物；目录只创建实际需要的文件，不生成占位文档：

```text
deep-learning/
├── README.md                              # 阅读导航与实验单元映射
├── design/
│   ├── 00-设计总览.md
│   └── mechanisms/                        # 多个独立核心思路时按需拆分
│       └── <机制>.md
├── network/
│   ├── 00-总体网络结构与分析.md
│   ├── modules/
│   │   ├── 01-<主要模块>.md
│   │   └── 02-<主要模块>.md
│   └── model-source/
│       ├── SOURCE-MANIFEST.md
│       └── <按仓库相对路径镜像的原始源码>
└── training/
    ├── 00-训练总览与复现入口.md
    ├── datasets/
    │   └── <数据集或数据组合>.md
    └── recipes/
        └── <任务-模型-数据集>.md
```

`survey` 可将模块细节收拢到网络总览；`standard` 和 `deep` 对每个主要模块分别成文。主要模块是满足至少一项的项目内结构：承担独立语义职责、拥有自定义前向逻辑、具有独立配置/权重、被多个路径复用，或形成明确的 stage/backbone/neck/head/encoder/decoder 边界。仅由常规层重复堆叠且行为一致的 block 族写一篇参数化分析，不为每个实例或基础算子单独建文档。

`deep-learning/README.md` 是该专题的唯一导航入口，以实验单元为行，链接对应的设计机制、总体网络、模块文档、数据集、训练 recipe、源码清单和证据状态，使读者无需猜测不同模型、数据与参数的组合关系。

## 思路设计

回答以下问题：

- 目标任务、输入输出、约束和评价目标是什么？现有方法的哪个缺口促成此设计？
- 核心假设、信息流与归纳偏置是什么？每项主要设计如何服务目标，而非只罗列模块名？
- 训练目标、网络结构、数据处理与推理方式如何共同实现该思路？
- 相对基线新增、替换或删除了什么；获得的性质、代价和适用边界是什么？

论文、README 或注释可证明作者声明的动机；源码和实验只能证明实现与观察结果。两类证据冲突时分别陈述，不用代码行为反向杜撰作者意图。

将共同问题、核心假设、整体方法和取舍写入 `design/00-设计总览.md`。只有多个机制拥有不同动机、证据和适用边界时，才在 `design/mechanisms/` 分篇；总览链接并综合它们，不重复详细论证。

## 网络结构与完整原始实现

从公开构建入口追踪一条完整的 `input → output/loss` 路径，并覆盖默认模型及分析范围内的主要变体。

网络结构分析至少包含：

- 模型构建入口、注册名、配置选择过程、顶层模块树和前向传播顺序。
- 输入/输出张量的语义、shape、dtype；各阶段的尺寸、通道或 embedding 维度变化。
- 每个项目内自定义模块的职责、关键算子、参数或超参数、残差/跳连、归一化、激活、注意力、融合与条件分支。
- 参数初始化、预训练权重加载、冻结/解冻、训练态与推理态差异。
- loss/head/decoder/post-processing 与主干网络的接缝；可由代码或运行结果确认时，给出总参数量及主要模块参数量。

先完成 `network/modules/` 中的主要模块分析，再编写 `network/00-总体网络结构与分析.md`。每篇模块文档必须包含：

- 模块职责、源码入口、构造参数和直接依赖。
- 输入输出 tensor 的语义、shape/dtype、约束和变化规则。
- 按真实 `forward` 控制流解释的子模块、关键算子、分支、残差/跳连和 train/eval 差异。
- 一幅 fenced `text` 代码块中的 plaintext 子网络图；节点、边和顺序必须能逐项回溯到源码，分支与汇合显式画出，动态维度使用符号而非猜测数值。
- 该模块为何存在、对整体设计的贡献、代价、变体和已知边界。
- 指向原始源码快照、证据 ID、上游模块和下游模块的链接。

`network/00-总体网络结构与分析.md` 包含由各主要模块组合而成的完整 plaintext 网络图、端到端 tensor 变化、模块索引、跨模块数据/控制流、模型变体差异以及参数量分布。总图中的模块名称必须与模块文档一一对应并链接；总览负责组合关系，不复制各模块的详细分析。对循环、条件执行、权重共享和多输入/多输出使用明确的图例，图无法由静态源码唯一确定时标记 `inferred` 或 `unknown`。

在 `_项目分析/deep-learning/network/model-source/` 下按仓库相对路径镜像“实例化目标模型并完成前向传播”所需的全部项目内原始源码。模型类、自定义层、项目内公共依赖、head/loss 以及动态注册代码均纳入；代码必须逐字保留，不省略、不改写、不用伪代码替代。第三方框架源码不复制，改为记录依赖名、版本约束和被调用 API。生成 `SOURCE-MANIFEST.md`，逐项记录：

| Snapshot path | Original path | Revision | SHA-256 | Symbols | Why required |
|---|---|---|---|---|---|

若源码由生成器产生、依赖不可得、包含未纳入范围的私有组件或无法确认完整性，将缺口标记为 `unknown`；不得声称快照可独立运行。多套模型共享实现时只镜像一次，由结构文档链接到同一来源。

## 训练方式与复现 Recipe

沿实际训练入口追踪配置合并、数据加载、优化步骤、验证和 checkpoint 选择，记录最终生效值及其来源。至少覆盖：

### 数据

- 数据集名称、版本/发布日期、获取位置或项目脚本、许可证可确认项。
- 官方划分或自定义 split、样本数、过滤/清洗、标签映射与数据泄漏防护。
- 输入尺寸/序列长度、预处理、归一化、tokenization、数据增强及 train/val/test 差异。
- sampler、shuffle、class balancing、drop-last、动态 batching 和随机种子。

### 优化与运行参数

- epoch/step 数、optimizer 及全部非默认参数、基础学习率、调度器、warmup、weight decay、梯度裁剪。
- 每设备 batch size、设备/进程数、梯度累积步数，以及按代码语义计算的有效全局 batch size；常规数据并行下验证 `per-device × process count × accumulation steps`，存在多 crop、pair、token 或框架特殊语义时另行解释，不可将任一项笼统写成 `batch size`。
- 各 loss 项及权重、正负样本策略、正则化、EMA、冻结策略、初始化或预训练 checkpoint。
- 精度模式、分布式策略、硬件与显存、num workers、缓存、编译选项，以及可获得的训练耗时。
- seed 与确定性设置、日志/验证频率、评价指标、最佳 checkpoint 规则、early stopping 和恢复训练语义。

### 可执行复现说明

在 `training/00-训练总览与复现入口.md` 汇总环境、公共训练流程、实验矩阵和建议复现顺序。每个数据集或不可拆分的数据组合写入 `training/datasets/`，每个纳入范围的实验单元写入 `training/recipes/`。Recipe 文档包含：

1. 环境与依赖锁定依据。
2. 数据准备命令和期望目录结构。
3. 官方或仓库实际训练命令；若需整理为命令，标记为 `inferred`。
4. 一张规范化参数表，字段至少含 `Parameter`、`Effective value`、`Scope`、`Source`、`Status`、`Notes`。
5. 单卡、原仓库多卡和等效资源受限方案；等效方案必须解释 batch、学习率、归一化与调度变化，标记为建议而非原始配置。
6. 验证/评估命令、预期指标及容差；只有仓库证据支持时才给出预期数值。
7. 仍阻碍复现的未知项与最小补证动作。

参数来源按优先级追踪：实际运行保存的 resolved config/日志、命令行覆盖、目标实验配置、配置继承值、训练脚本默认值、文档声明。发现冲突时并列记录作用域和优先级，不自行挑选“最合理”的值。框架级隐式默认会影响结果时查询与锁定对应版本的官方文档；无法锁定版本则标记 `unknown`。

## 验收标准

- 每个纳入范围的实验单元都能映射到思路、网络变体、数据集、训练 recipe 和评价方式。
- `deep-learning/README.md` 能从每个实验单元无歧义地导航到全部相关产物。
- 默认或指定模型从构建入口到输出/loss 的项目内源码快照完整，`SOURCE-MANIFEST.md` 无未解释断点。
- `standard/deep` 下每个主要模块均有独立文档、源码一致的 plaintext 子图和关键 tensor 变化；总图覆盖完整前向链路且与模块文档一一对应。
- 训练表明确最终生效值、作用域和来源，尤其区分每设备与有效全局 batch size。
- 原始 recipe、分析者推断和资源受限建议彼此分离；缺失参数显式标记 `unknown`。
- 复现成功仅由实际执行与指标验证支持；未运行时表述为“复现说明”而非“已复现”。
