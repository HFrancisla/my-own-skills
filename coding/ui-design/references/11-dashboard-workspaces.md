# 11 · 工作区与仪表盘：围绕业务对象组织高密度界面

## 首屏主体

面向专家的后台与工作台通常应让用户直接接触**数据、对象列表或操作画布**，而非夸张的营销引导。确定：用户先判断什么、需要筛选什么、哪个异常优先响应、打开详情会发生什么。

## 信息架构套路（根据任务选择）

- **列表 + 详情**：大量实体需要检索与对比；列表保持可扫描，详情可抽屉或独立页。
- **画布 + 检查器**：节点、连接、流程与空间关系是核心对象；工具栏与状态层不能遮挡画布。
- **指标 + 证据 + 操作**：KPI 只作快速预警，必须能追溯到指标来源、时间范围、单位与详情。
- **时间线 + 当前状态**：作业、部署、事件响应；实时状态与历史记录明显区分。

不要只为好看塞四张 KPI 卡片；每张卡片应对应用户的具体判断或后续动作。

## 数据密度与表格

- 主列有清楚的对象识别；数字右对齐、单位明确、时间时区明示。
- 重要状态不能仅靠颜色，提供文字、形状或图标。
- 排序/筛选/分页有当前状态反馈；空结果区别于没有数据。
- 粘性表头/固定列要检查宽屏和窄屏的遮挡。
- 批量操作需显示影响范围；危险操作有合理确认与撤销/恢复机制。

## AI Agent 控制台的特殊状态

对于 AI Agent、作业队列和工作流界面，应明确 `queued / running / succeeded / failed / canceled` 的视觉与文案映射。展示最近更新时间、执行对象、失败原因或可进入的日志；不要虚构实际模型调用成功。运行中的进度若无法计算，应使用不确定进度反馈而非假定百分比。

## 设计检验问题

假如只能给用户五秒，他能否说出哪些对象正在异常、为什么需要关注、点击哪里继续？若不能，应优先重排信息，最后再改边角装饰。
