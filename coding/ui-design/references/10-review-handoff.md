# 10 · 独立评审交接：减少制作方偏见

本文件只负责**如何交接和协作**。何时开展概念放行、真实画面评审或 UX 走查，以及各项评审维度、放行标准，统一见 [15 专业评审](15-professional-review.md)。

## 评审事实包

独立评审者仅接收：

1. 用户目标、典型任务、主要使用者。
2. 必须遵守的品牌、设备、内容与技术边界。
3. **当下真实**截图/页面入口、视口、可检查的关键状态，或缺失说明。
4. 明确的评审类型：制作前概念 / 制作后画面 / 可操作 UX。

使用 [评审事实包模板](../templates/reviewer-brief.md)。制作方的自我评分、审美辩护、期待结论不进入事实包；概念评审只提供方向与线框，不能假装具备最终画面证据。

## 可直接交接的任务说明

> 请从首次接触的用户视角独立检查所给证据。先找主角、主动作及主要反馈；对可操作环境自行发现入口并执行任务。逐条报告位置/状态、观察、用户影响、P0–P3 优先级、建议与可重验的方法。缺少真实画面或操作能力的维度写“未验证”；辨识度结论指出产品依据，不给无法溯源的总分。

## 评审结果合并

主 Agent 按实际证据处理建议：修复影响任务的 P0/P1；对不符合品牌、用户任务或实现约束的建议写明拒绝理由。问题修复后只复核相关路径与相邻影响；不得把“已收到评审意见”算作“已修复”。

## 多 Agent 编辑边界

多个实现者可按页面或相互独立的设计方向分工；共享 Token、组件库和路由文件须指定**一个合并负责人**。评审者原则上只读；评审报告放任务工作区，最终合并、验证和交付由主 Agent 负责。
