# 09 · 视觉验收：每项结论对应可复核证据

本文件负责**如何取证与核查**；问题严重度、独立评审与放行标准统一见 [15 专业评审](15-professional-review.md)。

## 证据能力边界

| 证据 | 支持的结论 | 不支持的结论 |
| --- | --- | --- |
| 源码阅读 | 组件/样式/状态逻辑是否存在 | 实际排版可读、点击可用 |
| 构建、类型或自动化测试 | 被测试范围内的静态/执行正确性 | 实际视口的层级与观感 |
| 亲自查看实际截图 | 对应视口与状态的布局、文字与视觉反馈 | 页面完整交互路径 |
| 在浏览器执行操作 | 已走过的任务、反馈与失败恢复 | 未测试的设备或业务输入 |
| 键盘/无障碍工具检查 | 实际涉及的焦点、语义、对比度等 | 所有辅助技术的完整兼容性 |

**先有证据，后有结论**。脚本生成了 PNG 只代表“截图已保存”；未经实际查看，视觉仍属未验证。没有可运行页面时可以继续源码检查，但明确报告视觉/交互未验证。

## 按任务范围取证

- **新页面/整体改版：**至少在代表性宽屏和窄屏打开页面，看真实默认态、主动作、相关加载/空/错态，走一条核心路径；需要时再看 200% 缩放、中间视口和减少动画偏好。
- **已有页面精修：**保存相同视口/内容的前后观察，检查受影响组件与邻接区域；布局源头更改时扩大到共享组件实例。
- **局部修改：**检查改动与相邻区域；纯文案、无布局风险时可说明跳过截图的理由。
- **只读评审：**记录收到的证据形式和实际看过的状态；没有操作权限时勿写“交互通过”。

实际核查包括：文本溢出/遮挡、横向滚动是否有意、字体与单位清晰、主动作可见、状态不靠单色、焦点与键盘、响应式浮层、安全区、运行控制台新增错误和失败后恢复。只检查与目标任务和风险相关的项目，不为列表形式虚构已执行操作。

## 记录与复核

每条实际执行的检查附上：**入口/页面、视口、状态、操作步骤或截图路径、观察结果、通过/失败/受阻**。截图前隐藏敏感数据；留存路径按项目规则，不放入 Skill 包。示例任务工作区：

```text
.ui-design/<task-slug>/
  brief.md
  direction.md
  evidence/
    before-desktop.png
    after-desktop.png
    after-mobile.png
  review.md
```

这些只是建议名称；未生成的文件不要出现在交付报告里。发现问题时记录 `证据位置 → 实际观察 → 用户影响 → 修复 → 重验`。修复后重看受影响视口、状态与邻近回归。问题的 P0–P3 级别和可否放行由 [15 专业评审](15-professional-review.md) 统一判定。
