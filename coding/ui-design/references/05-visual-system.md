# 05 · 视觉系统：复用、映射、验收

本文件负责将已选方向落成一致的 Token、排版和组件外观。概念的**产品辨识度**由 [14 视觉辨识度](14-visual-distinctiveness.md) 定义，避免在视觉系统里再做一次方向探索。

## 先找唯一来源

优先级：**现有设计系统 → 扩展已有 Token → 没有系统时建立轻量 Token**。改共享组件/Token 前检查受影响页面，避免只为某个组件并行建立第二套系统。

| 杠杆 | 需要统一的决策 | 验证重点 |
| --- | --- | --- |
| 排版 | 展示/正文/标签/数字字号、字重和行高 | 多语言长文本、数值对齐、窄屏扫描 |
| 色彩 | 背景/表面/文本/动作/焦点/语义状态 | 对比度与状态不只靠颜色 |
| 空间 | 内容密度、内部间距、页面栅格 | 主要对象是否比装饰更突出 |
| 边界 | 分隔线、圆角、阴影、层级 | 去掉冗余容器后对象关系仍清楚 |
| 图形 | 图标、图表、品牌图像的统一语法 | 图形是否传递内容且有合法来源 |

若项目没有 Token，可从 `../templates/design-tokens.css` 参考一个简版命名体系，再按项目习惯映射。模板色值是演示，不是必须使用的品牌色。

## 可访问性验证

根据项目适用的规范检查实际组合中的文本、控件边界、焦点和语义状态。通常正文文本对比至少 **4.5:1**、大文本至少 **3:1**、必要非文本状态指示至少 **3:1**；豁免按具体标准核对。以真实背景和实际尺寸计算或测试，不只凭设计稿的主观观感。

## 减法门槛

每个重复的标题、卡片容器、边框、阴影、渐变或动画，都要能解释为“帮助用户识别对象、理解状态或完成动作”。无法解释的装饰优先移除；同时保留业务字段、单位、错误原因和行动入口。

**完成条件：**主要页面复用同一 Token 语义、关键层级可读、状态和焦点有非颜色线索，新增的视觉元素有明确功能。真实渲染后的结果仍需按 [09 视觉验收](09-visual-validation.md) 检查。
