# 13 · 概念探索：先分化，再收敛

**触发：**新产品、新页面、全新组件或整体视觉改版。已选方向内的局部扩展、精确参数修改跳过。用户明确要求多方案时，内部筛选之后再制作指定数量的可比成品。

## 生成三个真正不同的候选

以 [产品事实](02-product-context.md) 中核实的对象、任务、品牌和限制为共同输入，分别从以下源头构思：

1. **对象驱动**：让产品特有的实体、数据关系或操作对象决定页面骨架，例如依赖图、时间轴。
2. **任务驱动**：按用户最关键的判断或失败恢复路径组织视图，例如异常优先、追踪到根因。
3. **媒介驱动**：取一种与产品含义相符的排版/图形语法，并转译为可实现的布局、字体和反馈。

每个候选仅需短小的 [候选表](../templates/concept-candidates.md)：一句概念、主角与动作、灰度首屏骨架、视觉语法及产品来源、一个有用的记忆点、素材/工程成本和主要失败风险。不必生成三套代码或无请求的对外成品。

## 筛选与完成条件

**先做硬约束淘汰**：任务、用户指定品牌、设备、无障碍、合法资产、实现资源任一不满足则退出候选；再按信息层级、产品关联、可扩展性和落地成本决定取舍。

候选之间至少在骨架、主要对象呈现或交互组织上具有不同机制；换色/圆角/阴影的版本算同一个候选。若全部不满足，回到事实包重构，不交付低质量备选。将入选理由和重要淘汰原因写入方向卡；默认仅对外呈现一个选定方向，除非用户要求比较。

如果有可隔离上下文的 Agent，可提供同一事实包让其独立提出备选；否则在当前 Agent 内完成探索，但不得称其为独立评审。选中方向进入 [03 设计方向](03-design-direction.md) 的灰度门槛，并用 [14 视觉辨识度](14-visual-distinctiveness.md) 验证产品来源。
