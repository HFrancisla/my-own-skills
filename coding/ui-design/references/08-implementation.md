# 08 · 工程实现：从已确认方向落到现有项目

## 不越界

本 Skill 决定**用户可见**的体验，不接管 API、数据库、授权策略与部署；用户指定需要这些改动时遵照其工程要求，未授权则不默默实现。先读项目的 `AGENTS.md`、设计系统文档、组件库约定和相关测试，项目规则优先。默认禁止无关格式化、依赖升级和全局重构。

## 源头优先

- UI 精修：从全局 Token、共享组件与布局源头修复，不在每页叠一堆覆盖 CSS。
- 原型转生产：只把原型当作视觉/交互标准；根据现有组件映射实现，不将演示 HTML 整页塞进生产环境。
- 新界面：先完成代表性页面或一条主任务流程，验证后再复用模式扩展。
- 交互：真实数据路径存在才说“已连接”；Mock 数据需可替换，不能假装生产持久化。
- 表单：使用项目已有校验、提交错误、权限与通知机制；注意异常和重复提交。

## 实现前写简短映射（中大型任务）

| 设计对象 | 现有实现/新组件 | 核心数据/状态 | 验证方式 |
| --- | --- | --- | --- |
| 任务列表 | 复用 `DataTable` | 加载、空、异常、分页 | 视口+状态截图 |
| 运行操作 | 扩展 `RunButton` | idle/running/success/error | 点击和错误重试 |
| 详情面板 | 复用 `Drawer` | open/closed 与焦点 | 键盘、窄屏 |

示例名称是占位符，实际须以项目组件为准。

## 回归测试范围

- **小改动**：关联单元检查或视觉检查。
- **中等改动**：类型检查、lint、受影响组件/页面测试、主要操作路径。
- **大改版**：受影响的集成流程、响应式、无障碍与回归检查；若项目要求构建或端到端测试应执行。

测试深度取决于用户要求、项目约定及风险，不设“永远不运行构建/全部测试”的硬规定。失败先分清与本次修改相关还是已有环境问题，真实告知结果。

## 证据不是工作产物本身

把草图、截图、设计报告放在任务目录，生产图标、组件、样式写到项目正式位置。不要把过程截图自动纳入前端产物；不要未经许可删除已有文件或清理用户数据。
