# 14 · 视觉辨识度：有身份，不靠猎奇

## 定义

辨识度是**产品来源可被识别的、稳定而有功能的设计语言**，不是随机换颜色、用粗字体或加过量动画。好的设计在不出现 Logo 的局部画面里仍能显出自己的秩序和气质；同时首要任务易于完成。

## 先锚定事实

依次回答：这款产品反复出现的**核心对象**是什么？用户在哪个时刻最需要确认、比较或行动？品牌给人的语气是什么？有没有可以合法复用的品牌资产、图形、摄影或数据模式？据此选一个「生成锚点」：真实数据结构、产品特有操作、内容物性、使用环境、视觉传统或跨领域的表达方式。记下明确证据，拒绝「因为看起来高级」。

## 六项可实施的视觉语法

1. **骨架**：工作对象的空间关系、阅读入口、导航层级、模块比例与留白，不默认三列卡片。
2. **字体**：展示标题、正文、数字与标签的差异，以及在长文、短标签和多语言下的韧性。
3. **色彩**：色源与语义用途（底色、强调、状态），不能把品牌色随意代替错误/成功色。
4. **主视觉与材质**：产品图、数据形状、符号、排版主角等；没有必要时不使用插画。
5. **控件手感**：边界厚度、角半径、密度、焦点与选中态共同遵守的规则。
6. **交互记忆点**：选一个关键时刻（例如失败定位、运行结果归位、复杂步骤完成）加以清楚且克制的可见反馈；不依赖音效或动画完成理解。

在 [视觉身份模板](../templates/visual-fingerprint.md) 中填写「具体决定 → 产品依据 → 可观察证据 → 禁止行为」。优先让**1–2 处真正特别**，其他部分安静支撑。

## 三道辨识度检查

- **遮住品牌**：去掉 Logo 与名称，骨架/图形/交互仍能被解释为该产品的选择吗？如果所有内容都可以替换成任意 SaaS 文案，仍太泛。
- **去掉装饰**：把渐变、背景纹理、阴影、动画关掉，主角与主动作还突出吗？若不能，回到灰度结构。
- **并排同类**：与已证实的 1–2 个同类 UI 比较骨架、字体、颜色、主视觉、关键交互；只是「同样布局+颜色不同」判定同构换肤。没实际取得参考截图时标记为未验证。

## 什么时候要克制

企业后台、医疗、金融或高压力操作场景，要把**辨识度更多放在信息表达、操作反馈和一致性**，不要强迫强饱和色、异常排版或互动噱头。用户给定了设计系统时，优先以系统内的业务模式、图表、流程表达和关键反馈形成特色，不擅自推翻品牌。

最终允许回答：「没有刻意造型，因为产品的识别依赖某种独特的任务组织或内容呈现。」但必须给出具体证据，而非口头辩解。
