# 04 · 布局与响应式：依内容和输入方式决定结构

## 常见页面骨架

- **工作台 / 操作台**：对象集合、筛选、主工作区、详情面板与系统反馈；先保留工作空间。
- **信息浏览**：搜索、分类、筛选、结果、详情；内容主体优先，不强加营销 Hero。
- **编辑表单**：任务标题、分组字段、错误与帮助、固定或就近主动作；考虑未保存内容。
- **说服型页面**：核心价值、证据、产品展示、行动入口；首屏不要同时主推五件事。
- **移动端操作**：单列任务顺序、可触摸控件、渐进披露；不是机械缩小桌面布局。

## 视口策略

优先使用项目约定断点；没有约定时，至少用一个宽屏与一个窄屏代表性视口检查（例如 `1440×900` 与 `390×844`），并用一个中等宽度检查压缩行为。具体数字是测试样例，不是强制断点。

检查：

- 横向空间不足时，哪个内容折行、折叠、换行、变为抽屉或转成单列？
- 表格是否允许有语义的横向滚动，且能找到最重要的列？不要把数据压成无法阅读的窄列。
- 长中文标题、长英文单词、URL、数字、国际化文本是否溢出？
- 固定导航、浮层、底部按钮是否遮挡内容？键盘弹出后是否还能提交表单？
- 安全区、触摸目标、焦点环和 200% 缩放时布局是否可用？

## 版式取舍

先定内容容器与栅格，再定空间节奏。优先使用弹性的 `minmax()`、`max-width`、`grid`/`flex`；不使用大段绝对定位去模拟布局。按信息层级分配空间，而不是让所有卡片面积相同。

明确主次比：有主内容时，主区域应在面积、对比或位置上明显强于辅助面板。控制面板固定宽度前先确认最窄屏表现。可读文本行宽不要过长，表单标签与字段保持直接关联。

## 精准截图还原

1. 区分参考截图中的**真实比例信息**与可能由浏览器缩放、字体或裁切引入的差异。
2. 先复原外层容器宽度、主次区块、基线、间距、字体层级，再处理色板、边界和细节。
3. 保留原图无法显示的交互状态、可访问性和响应式适配的合理设计空间；不要为了像素相似牺牲功能。
4. 对比必须尽量采用同视口和同内容；不能同时改变窗口尺寸和版式后仍宣称精准吻合。
5. 参考图不包含移动端时，按信息结构推导移动布局，说明这部分是适配设计而非截图还原。

## 灰度结构自检

只看黑白层级，问：主角在哪里？主操作在哪里？列表如何扫描？异常如何出现？没有颜色还能识别控件类型吗？不通过时先减少并列权重与重复组件。
