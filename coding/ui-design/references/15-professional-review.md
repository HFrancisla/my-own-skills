# 15 · 专业评审：区分证据类型与放行条件

本文件是**评审的统一判断标准**。评审材料隔离与多 Agent 协作参见 [10 评审交接](10-review-handoff.md)；截图与操作取证细节参见 [09 视觉验收](09-visual-validation.md)。

## 三种评审，三种证明范围

| 类型与时点 | 必备输入 | 可以判断 | 不能声称 |
| --- | --- | --- | --- |
| 概念放行（制作前） | 任务事实、硬约束、灰度线框/方向卡 | 用户任务适配、结构和资产预算 | 最终画面已通过 |
| 真实视觉（制作后） | 实际渲染的截图/页面、视口、状态 | 层级、可读性、视觉语法、适配与辨识度 | 点击流程已可用 |
| UX 走查（可操作时） | 实际入口、场景、交互环境 | 入口发现、输入、执行、反馈、失败恢复和焦点 | 所有设备/输入均正确 |

有隔离上下文且能看图的评审者时，新建/整体改版与重要品牌页完成代表性画面后进行**至少一次独立视觉评审**；复杂主任务可加独立 UX 走查。没有独立能力，按同一标准自检，清楚标记「未独立评审」。不能通过同一个 Agent 切换角色来冒充独立性。

## 评审者必须检查的维度

| 维度 | 可观察问题 |
| --- | --- |
| 任务适配 | 首眼能否定位主角、主动作和当前状态 |
| 产品辨识度 | 结构、内容/图形或反馈是否由产品事实推导，而非模板换色 |
| 视觉层级 | 字体、留白、对比度、视线顺序和组件权重是否清楚 |
| 一致性 | 页面及状态间是否遵循同一视觉语法与组件约定 |
| 可用性 | 从入口能否执行主任务，等待/错误后能否恢复 |
| 响应式与无障碍 | 窄屏、缩放、键盘、焦点和状态辅助线索是否可用 |
| 落地风险 | 资产许可、性能、模拟数据和服务边界是否真实 |

每条发现按 **ID、P0–P3 严重度、具体位置/状态、实际观察、用户影响、修复动作、证据和重验结果**记录；报告使用 [专业评审模板](../templates/professional-review.md)。未见证据的维度填「未验证」，不打推测分数；审美偏好与实际阻断分开表达。

## 放行判断

- **P0：不放行。** 主要任务无法完成、关键信息/操作不可访问、事实或服务状态造假、未授权使用资产等。
- **P1：先修或披露阻碍。** 严重排版溢出、信息层级误导、失败无法恢复、明显违反已有品牌约束。
- **P2/P3：按影响与预算处理。** 局部一致性、细节与审美建议，在不阻断任务时可延后。
- **新设计辨识度不足：回到方向/骨架。** 仅通过加装饰无法解决概念与产品脱节；既有品牌小修改无需强造新视觉身份。

修复后必须复核受影响区域；无法取得实际画面或操作证据时不得对其放行。停止条件是高优先级问题有明确处理、风险已披露、已验证范围可追溯，而非达到某个主观总分。
