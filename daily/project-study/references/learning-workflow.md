# 学习流程

**渐进展开**：项目地图回答「有哪些模块、从哪里学」；局部学习链路回答「当前模块下一步怎么学」。只为正在学习的模块深入调查并设计步骤。

## 1. 定位阶段

确定项目、学习目标和源码基线（Git 分支、commit、工作树状态；非 Git 则说明），再按用户意图选择：

- **初识项目**：没有学习地图、用户希望系统认识项目 → 第 2 节。
- **开始具体模块**：用户选择了模块或具体行为 → 第 3 节。没有地图时，仅补足定位当前模块所需的项目概览。
- **继续学习**：用户请求续学且有记录 → 从 `progress.md`、当前模块文件及最近会话恢复实际带读位置，进入第 3 或第 4 节。记录不足时说明缺口，从有源码证据的位置继续。

**完成标准**：已定位本轮学习焦点和可信的源码基线；不以完整课程作为开始条件。

## 2. 首次：建立地图

1. **横向扫描**：查看 README、目录结构、构建配置、主要入口、子系统及其边界；挑少量代表文件核实结构。
2. **绘制项目地图**：写明主要模块、职责、代表路径和已观察到的模块关系；以「已核实 / 文档所述 / 待查」标识证据等级。
3. **给出学习方向**：按依赖与项目特点提出若干粗粒度方向，每个方向只说明学什么、学习价值、可能的入口及已知先修关系。
4. **呈现选择点**：展示地图和方向，推荐一个起点，让学员选择下一模块。用户只要求认识项目时，本轮在这里结束。

**完成标准**：学员能据此找到一个可继续探索的模块；地图上的实际路径可定位，未知关系有明确标识。此时详细源码链路、练习和验收标准留待进入模块后确定。

## 3. 进入模块：设计局部链路

1. **收窄目标**：确定学员想理解的行为、已有基础与当前模块边界。
2. **核实主链**：针对目标找入口、核心处理与结果或副作用；核对真实文件、符号、参数/状态变化和关键跳转。复杂分析参照[源码分析](code-analysis.md)。
3. **只展开近期步骤**：围绕已核实的主链安排当前步骤及约 1–3 个后续候选步骤。当前步骤有明确的源码位置和可观察掌握目标；远处的内容仍是方向。
4. **边学边调整**：根据源码发现与学员反馈补充、拆分、合并或跳过后续步骤；新认知若改变项目整体认识，再更新地图或方向。

**完成标准**：能指出当前步骤的代码依据、学习目标和下一动作。若关键链路尚未核实，保留「待查」并以核实为下一步，不把猜测包装成课程。只有进入该模块后才创建模块学习文件。

## 4. 源码带读与验收

每轮围绕一个当前步骤展开：交代目标及输入输出 → 展示并解释足以说明该步骤的一小段真实代码 → 沿一个已核实的调用或数据跳转追踪（适用时） → 让学员选择继续、提问或练习。

教学可在「基础讲解 → 源码示范 → 引导练习 → 独立验证」之间依反馈调整。练习只考实际教过的内容，独立验收让学员指出代码依据并解释职责、主链或关键取舍；运行型目标以真实运行证据为准。

状态依据：

- `in_progress`：当前模块正在学习或验证，一个项目同时最多一个学习焦点。
- `completed`：学员独立表现满足该模块已明确的掌握目标，有可追溯证据。Agent 已经调查或讲解完成不构成掌握证据。

**完成标准**：本轮实际讲授位置、学员反馈（或明确无反馈）和一个下一动作可记录；未掌握时继续或修订本模块，掌握后由学员选择下一方向。

## 5. 记录与续学

需要持久化时，查阅[产物结构](artifact-templates.md)：

- 首次只写地图 `overview.md`、方向 `directions.md` 和最小指针 `progress.md`。
- 进入模块后才创建 `modules/<slug>.md`。每次实际教学追加 `sessions/YYYY-MM-DD.md`，更新模块链路与 `progress.md`。
- 新发现只更新受影响的地图、方向或模块内容。续学以最近**实际讲过的代码**而不是 Agent 最后调查到的位置为准。

**完成标准**：记录中的源码位置、学员证据及唯一下一动作相互一致。
